기존 업체 테스트 계정의 관리 목록에도 연결되며, 실제 소유권·사업자 심사를 통과했다는 의미는 아닙니다.

## 정책과 판정

- 실내·야외 모두 허용하고 체중·견종·준비물·예방접종 제한을 두지 않습니다.
- `pets_allowed=true`, `details_complete=true`, `max_weight_kg=null`과 빈 제한 규칙을 저장합니다.
- 승인 정책 `conditions_json`도 실내·야외 체중 상한 없음, 필수 준비물 없음으로 일치시킵니다.
- 상세 응답은 `ENTRY_OK`, `policyDetailsComplete=true`, `unrestrictedFields`의 네 항목을 반환합니다.
- 실제 장소의 정보 부족을 제한 없음으로 바꾸는 작업은 아닙니다. 기존 실제 조사·공공 장소는 보존합니다.

## 입력과 반복 실행

```sh
python3 scripts/seed_unrestricted_places.py plan
python3 scripts/seed_unrestricted_places.py apply --env-file <권한 제한 임시 DB 연결 파일>
```

원본 목록은 `scripts/fixtures/unrestricted_places.json`입니다. 기존 시연 업체 계정·가상 증빙을
재사용하는 별도 SQL 시드로, 새로운 계정이나 실제 사업자 정보를 만들지 않습니다. V23 이상에서
수동으로만 실행하며 앱 시작·배포에 연결하지 않습니다.

별도 `seed_key=pawfit-unrestricted-notion-20261119`와 노션 행 ID를 manifest에 기록합니다.
동일 출처의 기존 입력은 재사용하고, 다른 출처와 같은 이름·예약된 가상 사업자 번호 충돌은 중단합니다.
재실행 때 기존 정책·숨김을 덮어쓰지 않으며 운영자가 수정한 결과가 시드 기대와 다르면 확인이 필요합니다.
최초 실행은 신규 9곳, 배포 DB 재실행은 신규 0곳으로 검증했습니다.

입력 전 스냅샷·기존 데이터 해시·입력 결과는 Git 제외 폴더 `.demo/unrestricted-places/`에 보관합니다.
DB 접속값·계정 비밀번호·QR 원본 토큰은 커밋하지 않으며 임시 연결 파일은 작업 후 삭제합니다.
별도 시드이므로 기존 시연 계정의 전체 reset 대상으로 자동 편입하지 않습니다.

## 검증 범위

- 로컬 PostgreSQL: 최초 9곳 입력, 재실행 0곳, 동일 ID 및 기존 데이터 보존.
- 배포 DB: 신규 9곳·업체 관리 목록 총 15곳. 기존 업체·정책·실제/공공 장소·계정·반려견·QR·방문·스탬프·응모의 해시 보존.
- 배포 API: 현재 시연 보호자 계정에 등록된 몽이 기준 9곳 모두 상세·검색·카테고리·성수 1.5km 지도에서 `ENTRY_OK` 확인.
- 함께 가요: 해당 시연 계정에는 검증 시점 몽이 한 마리만 있어 배포 API에서 2마리 선택을 실행하지 않았습니다. 서로 다른 체중의 2마리를 함께 선택하는 허용 판정은 Java 통합 테스트로 확인합니다.
- 제한 없는 정책은 특정 반려견 ID나 품종을 예외 처리하지 않습니다. 요구 조건이 없어 모든 소유 반려견 선택에 같은 허용 판정이 적용됩니다.
- 기존 댕댕로드 스탬프는 1개로 유지됐습니다. QR 재발급·방문 인증·이벤트 참여 업체 추가는 실행하지 않았습니다.

앱은 성수 주변으로 이동하거나 장소명으로 검색해 새 데이터를 조회합니다. 이미 열려 있던 화면에
반영되지 않으면 지도 화면을 다시 열거나 앱을 재실행합니다. 데이터 추가만으로 앱 재빌드는 필요하지 않습니다.
